# Codex 任务模板

每次给 `Codex` 下任务时，尽量使用下面这个模板。目标是减少来回沟通，让任务更容易一次做对。

## 推荐模板

```md
目标：
- 这次要解决什么问题

背景：
- 当前现象 / 现有实现 / 相关上下文

影响范围：
- 允许修改哪些模块、页面、接口或文档

明确不做：
- 这次不要顺手改什么

验收标准：
- 用户层面或代码层面，什么算完成

最小验证：
- 这次至少需要跑哪些命令或检查哪些行为

文档要求：
- 是否需要同步 README、docs、注释或测试
```

## 推荐写法

- 目标只写一个主目标
- 如果是修 bug，写清“当前错误行为”和“期望正确行为”
- 如果只允许小修，直接写“不要重构”
- 如果涉及高风险区，明确指出不能改接口或不能改存储策略
- 如果你准备频繁 commit，直接要求“改动保持单一目的，便于拆 commit”

## 示例 1：普通修复

```md
目标：
- 修复聊天会话列表在删除后没有及时刷新的问题

背景：
- 当前删除会话成功后，右侧列表偶发保留旧项，刷新页面才恢复

影响范围：
- 只允许修改前端会话列表和相关请求逻辑

明确不做：
- 不改后端接口
- 不做样式重构

验收标准：
- 删除成功后列表立即移除该会话
- 当前选中状态正确切换

最小验证：
- npm run build

文档要求：
- 无需更新 README
```

## 示例 2：高风险后端改动

```md
目标：
- 为 refresh token 校验补一个缺失的异常处理分支

背景：
- 某些无效 token 场景会返回不一致的错误信息

影响范围：
- 允许修改 token session service、相关 API endpoint、对应测试

明确不做：
- 不调整 token 结构
- 不修改存储后端切换策略

验收标准：
- 无效 token 返回统一错误
- 已有正常刷新流程不受影响

最小验证：
- npm run test

文档要求：
- 若接口行为文字说明变更，同步更新 docs
```

## Codex 输出要求

每次任务完成后，结果说明至少包含：

- 改了什么
- 为什么这样改
- 跑了什么验证
- 没跑什么验证
- 还有什么剩余风险
