# 手工自检清单

这份清单用于替代第一版 `git hook`。每次准备 commit 或 push 前，快速过一遍即可。

## commit 前

- 这次改动是否只有一个主目标
- 是否误改了无关文件
- 是否留有临时日志、注释、测试代码、占位实现
- commit message 是否能准确描述本次改动
- 是否已经做了与改动相匹配的最小验证

## push 前

- 当前分支是否适合同步到另一台设备
- 是否存在明显半成品、断链改动、无法运行的状态
- 高风险改动是否已经补测试或说明风险
- 如果行为、接口、运行方式变了，相关文档是否已更新

## 验证命令参考

按改动范围选择，不要求每次全跑：

```powershell
npm run lint
npm run typecheck
npm run test
npm run build
npm run validate
```

## 常见拦截点

遇到下面这些情况，建议不要急着 commit 或 push：

- 还没确认改动边界，代码处于试错状态
- 一个提交里混入了修复、重构、样式、文档等多个目标
- 高风险区域已经改动，但没有任何验证
- 文档和实现明显不一致

## 最低通过标准

满足以下条件即可认为这次改动适合同步：

- 改动目的单一
- 代码状态完整
- 验证结果清楚
- 需要同步的文档和测试已同步到位
